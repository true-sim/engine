# Engine review, 2026-10-31

What this covers:
- every module: platform, vulkan, graph, render (geometry and shading), scene, xr, demo, build;
- judged on flexibility, performance, extensibility, API design and code design;
- engine v0.88.0.

How it was done:
- Five reviewers read the code, one area each.
- A fresh verifier then checked **every** finding against the code.
- Each finding came back as confirmed, partly right (narrower or a different mechanism than claimed), or wrong.
- Only what held up is listed here, ranked within each section. Wrong claims are listed at the end.
- Paths are relative to each module's `src/main` (Java) or `render/src/main/slang` (shaders).

## 1. Bugs (confirmed)

### Can corrupt frames or hang the GPU

1. **Visibility-buffer tile lists use two different strides under dynamic resolution.**
   - **Where:**
     - `VisibilityBufferShading.java:134-138, 167-169` spaces the per-bin lists by the full-image tile count.
     - `resolve.slang:103-107` (`tileList`) spaces them by the render-region tile count.
   - **Effect:** whenever the region is smaller than the image (dynamic resolution), bins after 0:
     - read their indirect arguments from another bin's header or from the middle of a tile array;
     - leave pixels unshaded;
     - can dispatch tile words as group counts (more than 65,535), which is undefined behavior and a possible GPU hang.
   - **Fix:** one stride on both sides. Push the full-image tile count and use it in `tileList`.

2. **A scene upload can be taken by the wrong pass under parallel recording.**
   - **Where:** `RecordBuffer.upload` (vulkan `RecordBuffer.java:224`) ignores `inPasses`.
   - **Callers:**
     - `MeshletRenderer.cull` (`:651`)
     - `ClassicLodGeometry.select` (`:396`)
     - `RayTracing.buildTopLevel` (`:839`)
   - **Mechanism:** with `FrameGraph.parallel`, chunks record in any CPU order. Whichever of these passes records first takes the scatter, and after a grow it also takes the old-to-new copy. That work lands in a command buffer that is later in GPU order than the declared "scene upload" pass.
   - **Effect:** readers in between see stale instances, or uninitialized memory after `GpuScene` grew.
   - **Fix:** make `upload()` a no-op (or an assert) once `inPasses` is set. That covers all three callers.

3. **Bins that overflow leave holes in the index stream.**
   - **Where:** `meshlets/cull.slang:65-70`.
   - **Mechanism:** the meshlet reserves its index range (`InterlockedAdd drawCommand[6*bin+5]`) *before* the bin-capacity check returns. Later meshlets then raise `drawCommand[0]` past the reserved hole.
   - **Effect:** the draw consumes stale indices, so garbage triangles appear (only on overflow).
   - **Fix:** check capacity before reserving, or write degenerate indices for dropped slots.

4. **A frame graph can't recover from an exception during a frame.**
   - **Where:** `FrameGraph.java:637-660, 869-881, 1022`.
   - **Mechanism:**
     - `begun` is cleared only at the end of `submit`, and `frameSlots.end()` is skipped on a throw.
     - A throw in a pass body, in `prepare()` or in `build()` therefore makes every later `beginFrame` fail.
     - `prepare()` also swaps histories before `build()` can throw, so the graph is left half-updated.
   - **Fix:** try/finally that resets `begun`, resets the slot's pools, ends the slots and rethrows. Swap histories only after the build succeeds.

5. **A rebuild that removes every async pass drops a cross-queue wait.**
   - **Where:** `FrameGraph.java:951` computes `bothQueues` from the *new* build.
   - **Effect:** the previous frame's compute work can race the new graphics work on handed-over pooled images, histories, persistents and external buffers. This only hits compute work that nothing later in graphics depended on.
   - **Fix:** decide the wait from "the compute timeline advanced since this slot last waited", not from the current build.

### Deadlock or threading rule broken

6. **Lock-order inversion between `Bindless` and `Retiring`.**
   - **Where:** `Bindless.java:278-288`, `Retiring.java:53-73`.
   - **Mechanism:** `removeSampled(slot, retiring)` holds the Bindless lock and then takes Retiring's. `Retiring.release()` holds its own lock while running closures that take the Bindless lock.
   - **Effect:** two threads doing these at once deadlock.
   - **Fix:** `release()` collects the ready entries under its lock and closes them after unlocking. The two-argument removes call `add` outside their lock.

7. **`VulkanDevice.waitIdle()` takes no queue locks.**
   - **Where:** `VulkanDevice.java:747`.
   - **Mechanism:** `vkDeviceWaitIdle` requires exclusive access to every queue, but `Queue.submit` uses a lock per queue, and `submitAndWait` is documented as callable from several threads.
   - **Effect:** the swapchain's recreate, HDR and present-mode changes can collide with a loader thread's submit.
   - **Fix:** take the queue locks in a fixed order, or call `Queue.waitIdle()` on each queue.

8. **View constants are written from parallel recording threads.**
   - **Where:** `RenderView.refresh()`/`write()` (`:137-227`), `FrameBuffer.missed` (`:203-217`).
   - **Mechanism:**
     - The early cull, the late cull and classic select can refresh the same view from different workers.
     - `FrameBuffer` is documented as used from one thread at a time, yet its dirty-range min/max is unsynchronized.
   - **Effects:**
     - A lost update leaves a slot's copy stale for bytes that are not rewritten every frame.
     - A double refresh writes this frame's values into PREVIOUS_VIEW_PROJECTION and PREVIOUS_JITTER, which breaks motion vectors.
     - One `SceneGeometry` with both providers and a `SceneDraw` camera calls `view.set` twice every frame (`MeshletGeometry:44`, `ClassicLodGeometry:351`), so PREVIOUS_* is wrong on every frame.
   - **Fix:** refresh each view once per frame on the frame thread before recording; recording only reads.

9. **Lights' shadow ranges are shared by all views, but each view writes them.**
   - **Where:** `Lights.shadows()` (`Lights.java:194-203`) is called from per-view setups:
     - `CascadedShadowMaps:351`
     - `InlineRayShadows:74`
     - `RayTracedShadows:~102`
     - `ShadowMapShadows:82`
   - **Effect:** the last host write wins for every view, and a view whose technique lost reads table entries it never wrote. Parallel recording also races `FrameBuffer`'s bookkeeping.
   - **Fix:** move `shadowFirst/count` into each view's `ShadowTable`, with entries reserved through a small allocator.

### Wrong results

10. **Chunks over `maxChunks` are dropped silently.**
    - **Where:** `meshlets/instances.slang:89-93`, `MeshletRenderer:188`.
    - **Mechanism:**
      - The 65,535 × 64-meshlet budget is shared by all views culled together.
      - It counts *candidate* meshlets, including coarser levels, not visible ones.
      - `chunkCommand[3]` is never read, and `overflowed()` doesn't report the overflow.
    - **Effect:** instances vanish, and which ones depends on atomic order, so they flicker.
    - **Fix:** dispatch over Y like the expansion does, grow the buffer from a readable counter, and report it in `overflowed()`.

11. **`Materials.update` of a mask field doesn't reach the slot.**
    - **Where:** `Materials.java:308-345` updates the parameter block only. `write()` copies maskAlpha and maskTexture into the slot (`:468-469`), and alpha masking reads the slot (`materials.slang:114-126`).
    - **Effect:** updating `baseColor.a` or `baseColorTexture` per frame never changes masking or shadows.
    - **Fix:** a `mask` flag on `MaterialField`, so `update` also writes the slot word.

12. **Mesh and meshlet id limits are lower than the pool now allows.**
    - **Meshlet ids:** `CLASSIC_TRIANGLE = 0x80000000` (`common.slang:351`). Meshlet ids of 2^24 and up set bit 31 in `meshlet << 7`, so `resolve.slang:96/177` shades them as classic triangles. The pool's meshlet capacity has no matching cap (`GeometryPool:542`).
    - **Attribute offsets:** `(int) attributeBase` (`GeometryPool:430`) wraps past 4 GiB of attributes, and attribute growth is uncapped.
    - **Fix:** cap growth at these limits in `GeometryPool.place`, with clear errors.

13. **A material swap ignores `WHOLE`.**
    - **Where:** `SceneSync.swapMaterials` (`:370-377`) installs the new set without `ready()`.
    - **Effect:** a drawn renderable shows default or untextured materials, the pop-in `WHOLE` promises to prevent.
    - **Fix:** park the new set until it is ready, then swap.

14. **A mesh change destroys the renderable before the new mesh arrives.**
    - **Where:** `SceneSync.reconcile` (`:339-349`).
    - **Effect:**
      - The renderable vanishes until the new mesh uploads.
      - It loses its instance id (and the per-instance occlusion history with it).
      - Materials and textures that dropped to no users are removed from the GPU and re-uploaded.
    - **Fix:** take the new mesh and set first, keep the slot, and release the old ones after.

15. **Loader failures on the main thread leave assets stuck.**
    - **Upload throws** (`SceneResources` `placed`/`textureLoaded`, also `tryAdd(Prepared)`/`textures.add(Prepared)` with `prepareOn`):
      - the asset is never marked failed;
      - `loadingCount()` never reaches 0;
      - every renderable of that mesh never draws, and `WHOLE` materials wait forever;
      - a texture entry acquired midway leaks.
    - **Already failed in the cache:** an asset that failed before this scene asked for it is never marked failed either (`acquireMesh`/`acquireMaterial`/`materialLoaded` check only `get() != null`).
    - **Inserted before acquired:** `acquireMesh` (`:426-428`), `acquireMaterial` (`:592-594`) and `SceneSync.reconcile` (`:352-354`) insert map entries before `assets.acquire`. A missing loader or source then leaves a `ViewMesh` with `mesh == null` (an NPE later) and a release with no matching acquire.
    - **Fix:** catch the upload and route it to the failed path; check `state(ref) == FAILED` on acquire; acquire before inserting.

16. **Growth leaks I introduced today.**
    - `Materials.grow` never calls `oldTables.release()`, so every outgrown table (one GPU copy per frame slot plus the CPU master) lives until close.
    - `RecordBuffer.grow` allocates new `indices`/`changes` from an arena freed only at close.
    - A second `RecordBuffer.grow` before an upload closes the current buffer at once. That is unsafe if the first grow happened mid-frame. It should go through `retiring`.
    - `RayTracing.growMeshes` without frame slots keeps old tables until close.

17. **XR: an exception leaves the frame half done.**
    - **Where:** `Headset.render` (`:532-570`) has no try/finally.
    - **Effect:** an exception after `xrBeginFrame` or an acquire leaves the images acquired and the frame never ended, which wedges the session.
    - **Also:** `locate` requires both ORIENTATION and POSITION to be valid (`:601-604`), so a moment of lost positional tracking submits no layer.

18. **Minor confirmed bugs.**
    - `Switch.fallback()` says the graph rebuilds, but it never invalidates (`Switch.java:51-55`).
    - A switched-off producer's transient image does not hold its contents, as `Switch` documents (`:27`).
    - Placing one technique in two views through `t.when(S)` passes the check, because `placeOf` doesn't unwrap the `Switch` (`FrameGraph:1381-1394`, `Technique:71`). That is the pitfall the rule was written for.
    - A settings listener that throws (Window's thread check) escapes `set()` after the value is stored and stops later listeners, Presenter and FrameGraph included (`EngineSettings:176-177`).
    - `Swapchain.acquire`/`present` use `Vulkan.check`, so a device loss there isn't recorded (`Swapchain:371, 404`).
    - If `PipelineCache` fails in the device constructor, `bindless` leaks (`VulkanDevice:339-347`).
    - Forward shading treats inline ray shadows as lit (`NoRays`), and shades every non-zero material type as metallic-roughness defaults (`common.slang:482-494`). Swapping it with the visibility buffer changes the image.
    - `CascadedShadowMaps` takes `near = viewProjection[14]`, which is only right for an infinite reverse-Z perspective camera. An orthographic main camera breaks the splits.

## 2. Performance (confirmed, by value)

1. **Culling atomics.**
   - **Where:** `cull.slang:65-82`.
   - **Problem:** six global atomics per visible meshlet on a few addresses.
   - **Fix:** aggregate per wave (count bits and prefix per bin, one add per wave). Derive the maxima once per workgroup.

2. **Instance-to-cull granularity.**
   - **Where:** `instances.slang:86`, `MeshletRenderer:721`.
   - **Problem:** one 64-thread workgroup per chunk, even for an instance with 2 meshlets. The instance pass costs highWater × views, and holes still cost a thread.
   - **Fix:** pack small ranges from several instances into one chunk (prefix-sum compaction).

3. **Visibility-buffer bin storage.**
   - **Where:** `VisibilityBufferShading:139-141`.
   - **Problem:** a full-screen tile list per bin, including bins with no variant, and the whole buffer cleared every frame. That is about 130 KB per bin at 1080p and grows with types × 2^FEATURE_BITS.
   - **Fix:** one shared tile array with per-bin counts. Clear only the headers.

4. **Top level is rebuilt from scratch.**
   - **Where:** `RayTracing:840-893`.
   - **Problem:** any instance change rebuilds the whole top level (`MODE_BUILD`, no `ALLOW_UPDATE`). Two scenes sharing one `RayTracing` flip the skip cache and pay two full builds per frame.
   - **Fix:** refit with `MODE_UPDATE` when only transforms changed, with a full rebuild periodically or on membership changes. One top level per scene.

5. **Shadows.**
   - **Where:** PCF in `lights.slang:224-249`; cascade choice in `:302-311`.
   - **Problem:** PCF does 9 loads with no comparison sampler or gather. Cascades switch hard with no blend. Every map is redrawn every frame.
   - **Fix:** `GatherCmp` with a comparison sampler, blend or dither at splits, and cache static casters or maps.

6. **Light clustering.**
   - **Where:** `cluster.slang:61-91`.
   - **Problem:** one thread per cluster tests every light (softened by groupshared batches), and spots are tested as spheres.
   - **Fix:** frustum-cull lights first, then a tile mask plus z-bins.

7. **`ExternalBuffer` size change means a full rebuild** (`ExternalBuffer:31-35`).
   - This is consistent with the bounds checks, and growth is rare.
   - But `startTooling` calls `waitIdle()` on every rebuild while readbacks or timings are on (`FrameGraph:1615`), turning each growth into a GPU stall.

8. **Cross-queue waits are conservative.**
   - **Where:** `FrameGraph:1034`, `GraphCompiler:839-848`.
   - **Problem:** waits use `ALL_COMMANDS`, and a queue switch resets the source to `ALL_COMMANDS`/`MEMORY_WRITE`. Together they give away much of the overlap async compute is for.
   - **Fix:** carry the consumers' stages into the waits.

9. **Upload barriers at frame start** (`FrameUploads:307-318`).
   - Two `ALL_COMMANDS` barriers whenever uploads are pending.
   - Only textures and ray tracing still use this path; scene data uploads in the graph pass without them.

10. **Setup paths serialize.**
    - `GpuBuffer.write` on a device-local buffer stages through RANDOM-access memory and waits.
    - `submitAndWait` holds its lock across the GPU wait, so loader threads run one at a time.
    - The transfer queue is never used.

11. **`FrameBuffer` costs.**
    - Mirrored copies are host-cached memory the CPU never reads; write-combined memory would do, though single-slot mode does need RANDOM.
    - One dirty range per slot means two writes at opposite ends copy everything between.

12. **Scene sync.**
    - With nothing drawn yet, any changed node triggers `rewriteAll` (`SceneSync:199`).
    - Waiting items re-check `ready()` every update.
    - Small next to the rest.

## 3. API and code design (confirmed)

1. **Too many ways to bind a camera.**
   - A camera reaches a `RenderView` through `RenderView.set`, `SceneGeometry.setView`, `SceneView.set` and a `SceneDraw`'s camera.
   - The last one forces `casterDetail` and `MODE_LIT` every frame.
   - `RenderView`, `SceneView`, `ViewPort` and `Camera` overlap without a stated owner of the binding.

2. **`GpuScene` instance writes take 14-15 positional primitives across five overloads.**
   - Drop the material argument and an int literal silently becomes x. Layers are a raw int.
   - Better: an allocation-free flyweight, e.g. `scene.edit(id).mesh(m).position(...)`.

3. **`FrameSlots` threading is redundant and unchecked.**
   - It is passed to every constructor, mismatches are never checked, and the name varies (`frames` in `Textures`).
   - Six classes default to `FrameSlots.single()`, so leaving out one argument silently gives single-buffering under a two-frame graph.
   - Options: a small context object, or derive the slots from the dependency and assert they match.

4. **Ownership is inconsistent.**
   - `SceneResources.close()` leaves the pool, materials and textures open, while the README builds them inline and never closes them.
   - `SceneGeometry.createView` and `CascadedShadowMaps` take ownership implicitly through `port.own`.
   - Pick one rule and fix the README.

5. **Hidden side effect in `SceneSync`.** Its constructor calls `gpu.setMaterials(...)` (`:159`), and only the pool is compared, so a second sync silently overwrites the table. Setter styles are mixed (`setMaterials` vs fluent `loading()`).

6. **God classes.**
   - FrameGraph: about 100 fields, about 45 copied out of `CompiledGraph` per build. It does registry, execution, recording, histories and tooling.
   - MeshletRenderer: 903 lines, 18 bin pipelines, and two APIs (immediate and graph).
   - RayTracing: 1,033 lines; the synchronous `add()` repeats the deferred path's geometry setup and uses one query pool per mesh.
   - Splitting them (executor, recorder and histories; draw-path strategies; bottom levels and top level) would make additions local.

7. **Push constants filled by hand at 8 sites.** The same addresses (`meshTable`, `instances`, `positions`, ...) are copied into push blocks at 8 sites. Offsets are generated, but `ids.slang`'s `unused[10] // materials at byte 80` is coupled by hand. A per-frame scene-tables struct behind one pointer would make a new per-instance stream one edit.

8. **Raw arrays and sentinels.**
   - GraphCompiler barriers are `long[13]` with magic indices.
   - MeshletRenderer uses `colorView == 0` to mean depth only, a `boolean late`, and int `MODE_*`.

9. **Geometry providers can't be extended.** `SceneGeometry.renderer()` uses `instanceof` over the two concrete providers, so a third provider (skinned, particles) can't plug in. Nothing checks that providers share a renderer.

10. **`FrameUploads` and `RecordBuffer` say the same thing differently.** `flush*` vs `upload*`. `RecordBuffer` is only partly `synchronized`, which buys nothing.

11. **Scene loader API (mine, from today).**
    - `loading(asset, mode)` is global across scenes, a mode on a mesh does nothing, and entries are never pruned.
    - `awaitLoaded` waits for STREAM assets too, contradicting its own example.
    - `awaitLoaded` blocks the main thread: no present, no events, no `xrWaitFrame`. That makes it a poor fit for a loading screen; a non-blocking `progress()` with running counts would fit better.
    - `prepareOn(lane)` and `awaitLoaded(tasks)` can't be checked to share a scheduler.

12. **Inconsistent construction in vulkan.**
    - `GpuBuffer` uses factories; `GpuImage` mixes constructors, `mipmapped`, and `create` with `int` vs `Format`.
    - `FrameBuffer.create` is a factory, while `RecordBuffer` and `FrameUploads` use constructors.

13. **Naming collisions.** "Scene" means six different things, and "Loading" means a policy, a status and a lookup.

14. **Cross-module and build.**
    - The demo bypasses engine-scene entirely, so the new loader path has no benchmark.
    - engine-xr depends on engine-render for `Camera` alone.
    - Versions are hard-coded in several build files.

## 4. Flexibility and extensibility (confirmed)

1. **Adding a material feature touches about six places.**
   - Clearcoat is hard-coded in the Slang shading, `Surface` and `MaterialFeatures.fromValues`.
   - Raising FEATURE_BITS past 3 without growing `features[3]` and the 64-thread classify clear would write past the slot.
   - It can't overflow today (FEATURE_BITS = 1), but nothing guards it.
   - Fix: generate the dispatch from `[MaterialFeature]` the way types are generated, plus static asserts.

2. **`Pipeline.Graphics` hard-codes most state.** No blending (so no transparency or UI), 1 sample, no `viewMask` (no multiview for XR), triangle lists only, fixed depth test, no stencil, no depth bias.

3. **Async compute can't touch external, persistent or texture images** (`GraphCompiler:172`). Accumulation or simulation images can never run async. Aliasing is whole-slot reuse of identical descriptors only.

4. **`Lights` is a fixed, index-addressed array.** It has a contiguous count, unlike the growing tables, and techniques hold raw indices.

5. **`Textures` handles RGBA8 only.** No BC/ASTC/HDR and no supplied mips. `remove()` frees a slot a material may still name.

6. **Ray-traced shadows treat alpha-masked geometry as opaque.** Documented in the README (`:292`), but foliage casts solid shadows with ray tracing and correct ones with shadow maps.

7. **XR tracking origin is translation only.** No snap turn, vehicles or world scale.

8. **Bindless limits are constants.** Slot counts are not checked against device limits, and the device owns the layout.

9. **Platform drops events.** DPI change, occlusion, IME composition, file drop and enter/leave events have no hook.

10. **Mesh-id reuse isn't followed.** Classic LOD doesn't follow removals; this is documented, but nothing enforces it. Pool removal listeners would close it.

## 5. Claims that did not hold

- **"Frame-slot retiring is unsafe because FrameSlots sees no fence."** Wrong for the graph: it waits on both timelines per slot before beginning it. It only applies to caller-managed shared slots, as documented.
- **"Platform passes bitmasks as raw ints though `KeyModifiers`/`PenState` exist."** Wrong: those ints are those encodings, deliberately allocation-free.
- **"`SceneResources.close()` causes use-after-free on the pool/textures."** Wrong: workers touch only the device. The real risk is closing the *device* with prepares running.
- **"A throwing upload aborts the cache's drain for other assets."** Wrong: `drainCompleted` runs every handler and rethrows after. The stuck-asset part stands (section 1, item 15).
- **"Late cull may test against a pyramid from a different camera."** Wrong: the GPU reads the final constants after recording.
- **"Light-buffer setups race GPU work already submitted."** Wrong: the graph submits after all chunks finish recording.
- **"Frame-start uploads race an async first pass" (as a current bug).** Only latent: scene data uploads in a declared pass now. Only textures and ray-tracing builds still use frame start, and no current async pass reads them.
- **"`MeshletRenderer` could get frame slots from the scene."** Wrong: `GpuScene` exposes none.
- **Partly-right claims** were downgraded in place above, e.g. `int...` overloads are redundant but not ambiguous, and `Images.transition`'s single level is documented and all callers fit.

## 6. Strengths worth keeping

- **Allocation-free per-frame paths, enforced by a build check.** The record and submit path writes raw structs, uses per-worker pools, and submits in a fixed order whatever the threading.
- **A device-free graph compiler.** It produces an immutable `CompiledGraph` that is testable alone. Barrier tracking per mip and layer, run over two frames, gets the frame seam and reused slots right. Typed keys, requests, implementations and modifiers extend well.
- **Double precision and deterministic data.** Instance positions are stored as high and low floats and drawn camera-relative, so a moving camera rewrites only its view. The change-list scatter costs CPU per changed instance. Ids and ranges are deterministic.
- **Slang is the single source of truth.** Records, field constants and type entry points are generated from it, and shadow and light-list interfaces let techniques plug in without touching shading.
- **Streaming that never waits.** Deferred bottom-level builds, prepared uploads, and growth everywhere are all retired by frame slot.
- **Diagnostics and a typed settings system.** `Diagnostics` hooks with no-op defaults, typed `Setting<T>` keys with ranges, and build checks (allocation, purity, coverage).

## 7. Suggested fix order

1. **Bugs that corrupt or hang** (section 1, items 1–3). Each is small:
   - one stride;
   - `upload()` honouring `inPasses`;
   - capacity checked before reserving.
2. **Robustness** (items 4–7):
   - graph exception safety;
   - the async wait across rebuilds;
   - the Bindless/Retiring lock order;
   - `waitIdle` locking.
3. **Threading of per-view data** (items 8–9): refresh views once per frame on the frame thread, and per-view shadow ranges.
4. **My own fixes from today** (items 13–16):
   - the loader's failure paths;
   - swaps and mesh changes;
   - the growth leaks.
5. **Limits and overflow reporting** (items 10, 12).
6. **Performance items 1–4**, measured against the stream and stereo benchmarks first.
7. **API consolidation**: camera binding, instance writes, `FrameSlots` and ownership. These are breaking changes, best done together in one minor release.
